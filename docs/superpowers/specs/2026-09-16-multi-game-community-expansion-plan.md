# 멀티 게임 · 커뮤니티 확장 계획

2026-09-16. 현재 lolpamin(한 LoL 친구 모임의 MMR·미활동 관리)을 롤·오버워치·발로란트·배그
네 종목의 게임 모임 플랫폼으로 키우고, 소모임 같은 커뮤니티 앱의 게임 카테고리를
대체하는 데까지 가는 로드맵. 구현 스펙이 아니라 방향과 순서를 적은 문서다. 각 단계는
착수할 때 별도 스펙을 쓴다.

## 1. 전제

### 지금 코드에서 그대로 쓰는 것

| 부품 | 위치 | 종목 의존 |
|---|---|---|
| 회원 = 사람 하나, 디코 쪽·카톡 쪽 독립 도착, 흡수/해제 | `Member.mergedIntoId`, `absorb-member`, `release-member` | 없음 |
| 팀 평균 Elo, K=40, 참가 보너스 +3/+1 | `packages/core/src/mmr.ts` | 팀 vs 팀 + 승/패 종목이면 없음 |
| 분기 리셋 (소프트/하드), `RatingReset` 워터마크 | `reset-ratings`, `counted-games.ts` | 없음 |
| 카톡 export 파서, 멘션 워터마크, 미활동 판정 | `lib/kakao-import`, `core/inactivity.ts` | 없음 (채널 의존) |
| 뽑기 (대포·핀볼·팀짜기) | `components/draw` | 없음 |
| 수동 팀 빌더, 티어 점수 | `team-builder`, `core/tier.ts` | **있음** — 티어 참조표가 LoL 솔랭 |
| 관리자 로그인, 감사 로그 | `lib/auth`, `GameResult.createdById` | 없음 |

### 종목별로 갈리는 지점

| | 롤 | 오버워치 | 발로란트 | 배그 |
|---|---|---|---|---|
| 팀 크기 | 5v5 | 5v5 | 5v5 | 4인 스쿼드 × N팀 (내전은 보통 4~6팀) |
| 결과 형태 | 승/패 | 승/패 (무승부 드묾) | 승/패 | **순위** 1~N등 + 킬 |
| 레이팅 | 지금 Elo 그대로 | 그대로 | 그대로 | **교체** — 순위 기반 (Plackett-Luce 또는 다인 TrueSkill) |
| 외부 티어 | 솔랭 티어 (표 있음) | 경쟁전 티어 | 경쟁전 랭크 | 경쟁전 티어 |
| 결과 자동 수집 API | Riot Match-V5 커스텀 게임 지원 | 공식 API 없음 | Riot API 있으나 커스텀 게임 제한적 | PUBG API 커스텀 매치 조회 가능 |
| 모임 규모 | 10~40 | 10~30 | 10~30 | 16~40 |

핵심: 롤·오버워치·발로는 코드 90% 재사용. 배그만 레이팅 모듈이 다르다.

### 소모임이 하는 것과 우리가 하는 것

| 기능 | 소모임 | 우리 (현재) |
|---|---|---|
| 모임 검색·가입 | O | X |
| 정모 공지·참가 신청 | O | X |
| 출석·회비 | O | X (회비는 게임 모임에 필요 없음) |
| 실력 (레이팅·티어) | X | O |
| 팀 밸런스 | X | O |
| 유령 회원 감지 | X | O |
| 내전 기록·역사 | X | O |

전략은 **오른쪽 열을 먼저 채우고 왼쪽 열을 나중에 흡수**한다. 발견 기능부터 만들면
빈 검색 결과 문제에 걸린다.

## 2. 단계

### 0단계 — 기반: 멀티테넌트 + 종목 추상화

가장 먼저, 다른 것을 얹기 전에. 늦을수록 마이그레이션 비용이 곱으로 는다.

**데이터 모델**

```
Group          id, name, slug, discordGuildId?, kakaoRoomLabel?, createdAt
GroupSport     groupId, sport (LOL | OVERWATCH | VALORANT | PUBG), ratingStrategy, teamSize?
GroupMember    groupId, memberId, role (OWNER | ADMIN | MEMBER), joinedAt, lastActiveAt
SportProfile   groupMemberId, sport, mmr, tier, externalId (riotId / battletag / pubgName)
GameResult     + groupId, sport, format (TEAM_VS_TEAM | RANKED_FFA)
GameParticipant + placement? (배그), kills?
RatingReset    + groupId, sport
MentionLog     + groupId
Admin          → GroupMember.role 로 흡수. 전역 Admin은 운영자용으로만 남김
```

- `Member`는 사람. 여러 그룹에 속할 수 있다. 흡수/해제는 그대로 `Member` 단위.
- `mmr`, `tier`, `riotId`, `lastActiveAt`는 `Member`에서 `SportProfile` / `GroupMember`로
  옮긴다. 한 사람이 롤 모임과 발로 모임에 있으면 레이팅이 둘이어야 한다.
- 지금 DB는 그룹 하나·종목 하나로 마이그레이션. 기존 회원 전부 그 그룹에.

**레이팅 전략 인터페이스** (`packages/core`)

```ts
interface RatingStrategy {
  apply(before: Record<memberId, number>, result: GameOutcome): Record<memberId, number>;
}
// TeamElo (지금 mmr.ts), RankedFfa (배그용, 새로 작성)
```

`saveGameResult`는 `GroupSport.ratingStrategy`로 골라 부른다. 취소·리셋 로직은
전략과 무관하므로 그대로.

**티어 참조표** — `core/tier.ts`의 LoL 표를 `tiers/{lol,overwatch,valorant,pubg}.ts`로.
각 종목 티어 enum은 별도 (`LolTier`, `OverwatchTier`…), `SportProfile.tier`는 문자열로
저장하고 종목 모듈이 검증.

**나가는 것**: 이 단계에서 UI는 안 바뀐다. 마이그레이션 + 테스트 통과가 완료 조건.

### 1단계 — 입력 자동화: 관리자 없이 굴러가게

성장의 적은 입력 귀찮음. 관리자가 매 내전 10명을 손으로 찍는 모임은 3개월 안에 기록이
끊긴다. 모임이 안 죽어야 다음 단계가 의미 있다.

1. **디스코드 음성 활동 로거** (활동 소스 2호).
   봇이 `voiceStateUpdate`로 접속·퇴장을 기록 → `GroupMember.lastActiveAt` 갱신.
   카톡 export 옆에 나란히 두 번째 소스. 카톡 없는 모임(해외·발로 모임)은 이것만으로
   미활동 감지가 된다. 업로드 0.
2. **롤 내전 자동 가져오기**.
   Riot Match-V5로 커스텀 게임 조회. `riotId` 연결된 회원의 최근 커스텀 매치 →
   참가자·팀·승패를 `saveGameResult`에 넣기 전 확인 화면 한 번. 관리자 일은 "확인"
   클릭.
3. **봇 결과 입력** (API 없는 오버워치·발로용).
   팀장이 `/result win @a @b @c @d @e vs @f …` 또는 팀 빌더에서 짠 팀을 봇이 기억해
   `/result win blue`. 배그는 `/result 1 @a @b @c @d, 2 @e …`.
4. **배그 자동 가져오기**는 수요 확인 후. PUBG API로 커스텀 매치 조회는 되지만 파트너
   등급 키가 필요할 수 있다.

**측정**: 그룹당 주간 기록된 내전 수. 이게 0인 그룹은 죽은 그룹.

### 2단계 — 회원 앱: 매일 열 이유

소모임은 관리자 앱이다. 우리는 회원이 직접 여는 앱이 되어야 성장한다. 회비·출석 같은
소모임의 무거운 절반은 게임 모임에 필요 없으니 버린다.

1. **내 페이지**: MMR 그래프, 종목별 전적, 라이벌 (자주 붙는 상대와의 상대 전적),
   같은 팀 승률 높은 사람.
2. **시즌**: 분기 리셋을 "시즌 종료 이벤트"로. 시즌 순위표 스냅샷, 1~3위 뱃지,
   시즌 MVP(참가 수 × 승률). 리셋이 손실이 아니라 새 출발이 된다.
3. **내전 모집** (소모임 정모의 대체):
   `/내전 20:00` → 봇이 임베드에 참가 버튼 → 참가 목록 → 인원 차면 `team-builder`가
   자동 밸런스 제안 → 팀장 확정 → 결과 입력으로 이어짐. 모집·출석·팀·기록이 한 흐름.
   대기자(waitlist)는 카톡 파서가 이미 개념을 안다.
4. **알림**: 디코 DM. 내전 1시간 전, 내 순위 변동, 시즌 종료 D-3.
5. **로그인**: 관리자 비밀번호 로그인 → Discord OAuth. 회원이 자기 페이지를 보려면
   디코 로그인이 자연스럽다. 카톡 로그인은 한국 한정으로 나중에.

### 3단계 — 바이럴: 모임이 모임을 부르게

1. **공유 카드**: 시즌 결과·내전 결과를 이미지로 자동 생성 → 카톡·디코에 붙임.
   다른 모임 사람이 보고 찾아오는 경로.
2. **모임 공개 페이지**: `/g/{slug}` 순위표·최근 내전·활동률. 읽기는 지금도 공개다.
   새 멤버 초대가 링크 하나.
3. **교류전**: A 그룹 vs B 그룹 내전. 두 그룹 레이팅이 같은 풀에 들어간다 — 여기서
   처음 네트워크 효과가 생긴다. 소모임엔 없는 기능이고, 모임끼리 서로를 데려온다.
   레이팅 풀 분리 문제(그룹 내 Elo는 폐쇄 풀이라 그룹 간 비교 불가)는 교류전 전용
   글로벌 레이팅을 따로 두는 것으로 시작.

### 4단계 — 발견: 소모임 대체 완성

살아있는 그룹이 100개쯤 있을 때. 그 전에 만들면 빈 방.

1. **모임 검색**: 종목 × 실력대 × 활동 빈도 × 시간대. 소모임은 텍스트 소개뿐이지만
   우리는 "골드~플레, 주 2회 내전, 활동률 80%, 20~23시"를 데이터로 낸다.
2. **가입 흐름**: 검색 → 디코 서버 초대 → 봇이 `GroupMember` 생성 → 라이엇 ID /
   배틀태그 연결 → 티어 자동 → 첫 내전 팀 밸런스에 바로 반영.
3. **모임 만들기**: 봇 초대 한 번 = 그룹 생성. 30초 안에 `/mmr`가 나와야 한다.
4. **신뢰**: 활동률·평균 응답 시간·시즌 수를 그룹 카드에. 유령 모임이 검색 상단에
   못 온다.

## 3. 수익

게임 모임은 회비를 안 걷는다. 결제 주체는 모임장 한 명.

| 구간 | 무료 | 유료 (그룹당 월 ₩4,900 / $4) |
|---|---|---|
| 회원 수 | 20 | 무제한 |
| 관리자 | 1 | 여러 명 |
| 봇 명령 | 전부 | 전부 |
| 자동 가져오기 | 월 10회 | 무제한 |
| 미활동 자동 감지 | X | O |
| 시즌 히스토리 | 최근 1시즌 | 전체 |
| 발견 노출 | 기본 | 상단 |

유료 전환은 "관리자 시간을 아끼는 기능"(자동 입력·미활동 감지)에서만 나온다. 레이팅
표시만으로는 못 받는다. 무료 구간을 좁히면 성장이 죽으니 회원 수 상한은 넉넉히.

## 4. 유통

- 한국: 롤 커뮤니티(인벤·롤 갤), 디코 서버 목록 사이트, 소모임 게임 카테고리 안에서
  "우리 모임은 이거 씀" 공유 카드로.
- 글로벌: Discord App Directory, top.gg. 봇 명령은 영어 기본 + 로케일 alias
  (`/랭킹` ↔ `/ranking`).
- 카톡 파서는 한국 플러그인으로 격리. 해외는 디코 음성 로거만으로 미활동 감지.

## 5. 순서와 이유

```
0 멀티테넌트·종목 추상화   ← 늦을수록 비쌈
1 입력 자동화             ← 모임이 안 죽게
2 회원 앱·내전 모집        ← 매일 접점, 소모임 정모 흡수
3 공유·공개 페이지·교류전   ← 모임이 모임을 부름
4 발견                    ← 살아있는 그룹 100개 뒤
```

소모임은 4 → 2 순서로 만들어져 게임 카테고리가 약하다. 우리는 반대로 간다.

## 6. 종목별 착수 순서

1. **롤** — 지금. 자동 가져오기 API가 가장 좋다.
2. **발로란트** — 5v5 승패, 같은 Riot 계정 체계. 티어 표만 교체. 봇 결과 입력.
3. **오버워치** — 5v5 승패. API 없음, 봇 결과 입력. 배틀태그 연결.
4. **배그** — `RankedFfa` 전략 신규 + `placement` 컬럼. 수요 확인 후.

## 7. 코드 관점 첫 작업 3개

1. `Group` / `GroupMember` / `SportProfile` 마이그레이션. 기존 데이터를 그룹 하나로.
2. 디코 음성 로거 → `GroupMember.lastActiveAt`. 카톡 파서와 같은 자리에 두 번째 소스.
3. Riot Match-V5 커스텀 게임 가져오기 → 확인 화면 → `saveGameResult`.

## 8. 지표

| 단계 | 본다 | 안 본다 |
|---|---|---|
| 0–1 | 그룹당 주간 기록 내전 수 | 가입자 수 |
| 2 | 회원 주간 활성 (내 페이지·모집 참가) | 페이지뷰 |
| 3 | 공유 카드 → 신규 그룹 전환 | |
| 4 | 검색 → 가입 → 첫 내전 참가까지 완주율 | 검색 트래픽 |

## 9. 리스크

- **입력이 안 되면 다 무너짐** — 1단계가 전부. 오버워치·발로 API 부재는 봇 입력 UX로
  풀어야 하고, 그게 귀찮으면 그 종목은 안 큰다.
- **디코 봇 시장은 무료 천지** — 레이팅 봇은 이미 많다. 차별점은 "모임 관리"(미활동·
  시즌·모집)이지 레이팅이 아니다.
- **Riot API 정책** — 프로덕션 키 승인 필요, 레이트 리밋. 가져오기는 배치·캐시.
- **그룹 간 레이팅 비교 불가** — 그룹 내 Elo는 폐쇄 풀. 교류전·발견에서 "실력대"는
  외부 티어(솔랭)로 표시하고 내부 MMR은 그룹 안에서만 쓴다.
- **카톡 의존 잔재** — `Member.kakaoNickname` 매칭 키 등은 한국 그룹에서만 의미.
  0단계에서 카톡 필드를 `GroupMember`의 채널 프로필로 격리해야 해외 그룹 코드가 안
  더러워진다.
