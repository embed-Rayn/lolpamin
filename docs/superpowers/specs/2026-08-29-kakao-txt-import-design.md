# 카카오톡 대화 내보내기(txt) 기반 활동 수집 설계

**날짜:** 2026-08-29
**상태:** 설계 승인 완료, 구현 계획 작성 대기
**대체 대상:** `docs/superpowers/specs/2026-08-23-discord-kakao-integration-design.md`의 kakao-bot 컴포넌트

## 배경 및 목적

기존 계획(`docs/superpowers/plans/2026-08-24-kakao-bot-implementation.md`)대로 `node-kakao`(비공식 카카오톡 프로토콜 클라이언트)를 이용한 상시 접속 봇을 구현·검증했으나, 2026-08-25 검증 세션에서 다음이 확인되었다 (`docs/superpowers/reports/2026-08-25-kakao-bot-completion.md`):

- `node-kakao`가 하드코딩한 PC 클라이언트 버전(2021-11-21 배포분)이 카카오 서버의 최신 프로토콜 요구사항에 더 이상 맞지 않아 로그인 자체가 `-999 (UPGRADE_REQUIRED)`로 거부됨.
- 업스트림 저장소가 "Not Maintained"로 명시되어 있어 향후 복구를 기대하기 어려움.
- 사용자는 프로토콜 버전 스푸핑(계정 제재 위험) 대신 이 접근 자체를 중단하기로 판단.

이를 대체하기 위해, 관리자가 카카오톡 오픈채팅방의 "대화 내보내기" 기능(공식 기능, 계정 제재 위험 없음)으로 얻은 `.txt` 파일을 대시보드에 업로드하면, 그 자리에서 파싱해 기존과 동일한 활동 추적(멘션 기반 `lastActiveAt`/`MentionLog`)을 수행한다.

## 범위

**포함:**
- 카카오톡 대화 내보내기 txt 파일을 파싱해 `@멘션` 이벤트를 추출하는 순수 함수.
- 추출된 멘션을 기존 `Member`(`kakaoNickname` 매칭) / `MentionLog` 데이터에 반영하는 처리 로직.
- 대시보드에 파일 업로드 UI 및 처리 결과 요약 화면.
- 이전에 처리한 범위와 겹치는 재업로드 시 멘션을 중복 기록하지 않는 워터마크 로직.

**범위 밖:**
- `apps/kakao-bot`이 담당했던 실시간/상시 감시 — 이 설계는 관리자가 주기적으로 수동 업로드하는 배치 방식으로 완전히 대체한다 (실시간성 없음, 기존 스펙의 "완벽한 출석 기록이 아닌 대략적 활동 신호" 전제를 그대로 승계).
- 닉네임 변경 시 자동 재매칭 — 정확히 일치하는 `kakaoNickname`만 자동 매칭하며, 닉네임이 바뀌면 관리자가 대시보드에서 기존 계정 매핑 화면을 통해 수동으로 정리해야 한다.
- 발신자(메시지를 보낸 사람) 기반 출석 판정 — 기존과 동일하게 `@멘션 대상`만 활동 신호로 취급한다.
- 업로드 파일의 서버 영구 보관 — 파싱에 쓰고 버린다 (원문 감사 목적은 기존과 동일하게 `MentionLog.rawMessage`로 충분).

## 아키텍처

```
/apps
  /discord-bot        (변경 없음)
  /dashboard          (Next.js) — 회원 매핑, 게임 결과 입력, 미활동자 리포트, 카톡 내보내기 업로드(신규)
/packages
  /db                 (변경 없음 — 스키마 마이그레이션 없음)
  /core               (변경 없음)
```

`apps/kakao-bot`은 삭제한다. 그 안의 라이브러리 의존성 없는 순수 함수(`extract-mentions.ts`, `record-member-activity.ts`의 로직)는 `apps/dashboard/lib/kakao-import/`로 옮겨 재사용한다. 별도 프로세스·스케줄러·큐가 필요 없다 — 업로드 요청 처리 자체가 파싱과 DB 반영을 동기적으로 끝낸다.

### 검토한 대안

- **`@멘션` 대신 메시지 발신자를 활동 신호로 사용**: 내보내기 텍스트에 발신자 헤더가 항상 있어 파싱이 더 견고하지만, 사용자가 기존 방식(멘션 대상 기준) 유지를 선택함 — 매 세션 파싱하는 지금 이 재작업의 목적이 기존 활동 추적 의미를 유지하는 것이므로 그대로 승계.
- **닉네임 유사도(퍼지) 매칭**: 닉네임 일부 변경에도 대응 가능하지만 구현 복잡도와 오매칭 위험이 큼 — 사용자가 정확 일치만 선택.

## 데이터 모델

**스키마 변경 없음.** 기존 모델을 그대로 사용한다.

```
Member.kakaoNickname   // 매칭 키로 사용 (정확 일치)
Member.kakaoUserId     // 더 이상 채워지지 않음 — 컬럼은 과거 데이터 호환을 위해 유지, 마이그레이션 없음
Member.lastActiveAt    // 멘션 파싱 결과로 갱신
MentionLog             // 멘션 파싱 결과로 insert (memberId, mentionedAt, rawMessage)
```

## 파싱 로직

### 입력 포맷

```
게임구인방 님과 카카오톡 대화
저장한 날짜 : 2026-08-29 22:58:30
--------------- 2026년 8월 29일 토요일 ---------------
[박병준/94/늑 구#1003] [오전 12:46] 🔥도파민충전🔥
게임 : 자랭
...
1. @김복건/96/뚜비뚜밥#뚜비얌
```

파서는 다음 세 종류의 줄을 인식한다:

1. **날짜 구분선**: `--------------- YYYY년 M월 D일 요일 ---------------` — 이후 등장하는 메시지 헤더의 날짜로 사용.
2. **메시지 헤더**: `[발신자] [오전|오후 H:MM] 내용 첫 줄` — 새 메시지 시작. 발신자 문자열, 오전/오후+시:분, 그리고 그 줄의 나머지를 메시지 본문 첫 줄로 캡처.
3. **그 외 모든 줄** (빈 줄, "메시지가 삭제되었습니다." 같은 시스템 알림 줄 포함): 직전 메시지 본문에 이어붙인다. 직전 메시지가 없으면(파일 맨 앞 등) 버린다.

각 메시지가 완성되면(다음 메시지 헤더 또는 파일 끝에서 확정), 본문의 각 줄에서 `@`가 처음 나오는 위치를 찾아 그 이후 전체(trim)를 멘션된 닉네임으로 추출한다 — `@`가 줄 맨 앞에 오는 경우("@닉네임")뿐 아니라 이 채팅방의 실제 관례인 "번호. @닉네임"(예: "1. @김복건/96/뚜비뚜밥#뚜비얌")처럼 앞에 다른 텍스트가 붙는 경우도 그대로 잡아낸다. 한 메시지에 여러 멘션 줄이 있으면 각각 별도 이벤트로 처리한다.

- 함수: `parseKakaoExport(text: string): ParsedMention[]`
- `ParsedMention = { mentionedNickname: string; mentionedAt: Date; rawMessage: string }`
- 외부 의존성 없는 순수 함수 — `node-kakao` 등 카카오 관련 라이브러리를 전혀 참조하지 않는다.

### 알려진 한계 (설계상 수용)

- 내보내기 타임스탬프는 분(minute) 단위까지만 존재(초 없음) — 같은 분에 멘션이 여러 건 발생하고 마침 그 지점이 워터마크 경계와 겹치면 극히 드물게 중복 또는 누락이 있을 수 있다. 기존 kakao-bot 스펙의 "완벽한 출석 기록이 아닌 대략적 활동 신호" 전제 안에서 허용 가능한 오차로 본다.
- "번호. @닉네임" 한 줄 한 멘션 관례가 깨지는 경우(한 줄에 멘션 여러 개 + 다른 텍스트)는 오파싱 가능 — 실제 파일에서 문제가 확인되면 `#태그`로 끝나는 패턴만 인식하는 방식으로 교체한다.

## 업로드 처리

`apps/dashboard/lib/kakao-import/process-export.ts`:

1. `parseKakaoExport`로 업로드된 텍스트를 파싱.
2. `MAX(MentionLog.mentionedAt)`를 워터마크로 조회 (없으면 전체 처리).
3. 워터마크보다 이후(strictly after) 시각의 `ParsedMention`만 남기고 나머지는 "건너뜀"으로 집계.
4. 남은 각 멘션에 대해:
   - `kakaoNickname`이 정확히 일치하는 `Member`를 조회.
   - 있으면 `lastActiveAt` 갱신 + `MentionLog` insert.
   - 없으면 `kakaoNickname`만 채운 반쪽 `Member`를 생성한 뒤 동일하게 처리 (기존 kakao-bot의 "처음 보는 유저 자동 반쪽 레코드 생성" 동작을 kakaoUserId 대신 kakaoNickname 매칭으로 승계).
5. `{ newMembers: number; activityUpdates: number; skippedAsAlreadyProcessed: number }` 반환.

동시 업로드에 대한 별도 락은 두지 않는다 — 관리자 1인이 수동으로 업로드하는 저빈도 작업이라 동시 실행 경합 가능성이 무시할 수준.

## 대시보드 UI

- 새 페이지 `apps/dashboard/app/kakao-import/page.tsx` + 네비게이션 항목 "카톡 내보내기" 추가.
- `.txt` 파일 선택 + 업로드 버튼 → 서버 액션(`app/kakao-import/actions.ts`) 호출.
- 처리 후 요약 카드로 신규 회원 수, 활동 갱신 수, 건너뛴(중복) 멘션 수를 표시.

## 에러 처리 및 안정성

- 파일이 예상 포맷과 다르면(예: 메시지 헤더가 하나도 매칭되지 않음) 사용자에게 "파싱된 멘션이 0건입니다" 같은 안내만 하고 아무 것도 쓰지 않는다 (에러로 막지 않음 — 예: 멘션이 실제로 없는 조용한 날짜의 내보내기일 수도 있음).
- DB 반영은 한 업로드 전체를 트랜잭션으로 묶어, 처리 중간에 실패하면 부분 반영 없이 롤백한다.
- 카카오 계정/프로토콜에 의존하는 부분이 전혀 없으므로 계정 제재·프로토콜 breakage 리스크가 사라진다.

- UI는 소규모 내부 도구이므로 수동 테스트로 충분 (기존 스펙과 동일한 판단).
