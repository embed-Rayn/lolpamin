# 회원 데이터 유입·정리·편집 설계

**날짜:** 2026-08-31
**상태:** 설계 승인 대기
**관련 문서:** `docs/superpowers/specs/2026-08-23-discord-kakao-integration-design.md` (전체 시스템 설계), `docs/superpowers/specs/2026-08-29-kakao-txt-import-design.md` (카톡 임포트)

## 배경 및 목적

배포된 대시보드를 실제로 써보니 세 가지가 막혀 있었다.

**1. 디스코드 계정이 시스템에 들어올 경로가 없다.** 전체 설계 문서에는 "디스코드 서버에 새 멤버가 들어오면 해당 플랫폼 ID만 채운 반쪽 `Member` 레코드가 생성된다"고 적혀 있지만, 그 일을 할 컴포넌트가 구현되지 않았다. `apps/discord-bot`은 조회 전용이고 DB에 쓰는 코드가 없다. 결과적으로 `/link-accounts`의 미연결 디스코드 목록은 언제나 비어 있고, 계정 연결 기능 전체가 시작조차 못 한다.

**2. 실명을 입력할 방법이 없다.** `Member.realName`을 채우는 경로는 `linkMembers`가 카톡 닉네임을 파싱해 넣는 것 하나뿐이다. 1번 때문에 연결을 못 하니 실명은 계속 비어 있고, 화면에서 직접 타이핑할 수단도 없다.

**3. 카톡 닉네임의 괄호 표기가 같은 사람을 여러 명으로 만든다.** 실제 데이터에 `유승수/98/ModCow#KR98(7시30분 도착)` 같은 형태가 있다. 임포트는 닉네임을 정확히 일치시켜 매칭하므로, 도착 시간을 적은 날과 안 적은 날의 같은 사람이 별개 회원으로 쌓인다.

여기에 더해 회원 목록을 정렬할 수 없어 ELO 순으로 보는 것조차 안 된다.

## 범위

**포함:**

- 대시보드에서 디스코드 길드 회원을 가져와 반쪽 `Member` 레코드로 만드는 경로
- 카톡 닉네임의 괄호 표기 제거(정규화)와, 그에 따른 기존 데이터 정리·중복 병합
- 실명 자동 채우기(비어 있을 때만)와 화면에서의 직접 수정
- 회원 목록 정렬(실명 / 카톡 닉네임 / ELO)

**범위 밖:**

- 디스코드 계정과 카톡 계정의 자동 연결. 연결은 지금처럼 관리자가 `/link-accounts`에서 수동으로 한다.
- 실명 외 필드(나이, 라이엇 ID, ELO)의 화면 편집. ELO는 특히 경기 결과로 계산된 값이므로 사람이 덮어쓰지 않는다.
- 디스코드 실시간 이벤트 구독(새 멤버 입장 시 자동 생성). 관리자가 버튼을 눌러 가져온다.
- 스키마 변경. 이 작업은 기존 `Member` 필드만 사용한다.

## 디스코드 회원 가져오기

### 흐름

관리자가 `/link-accounts`에서 「디스코드 회원 가져오기」를 누르면, 서버 액션이 디스코드 REST API로 길드 멤버 목록을 받아 `Member`에 반영하고 `{ created, updated, skippedBots }` 요약을 돌려준다.

### 컴포넌트

- **`apps/dashboard/lib/discord/fetch-guild-members.ts`** (얇은 어댑터) — `fetchGuildMembers(token, guildId): Promise<DiscordGuildMember[]>`. `GET https://discord.com/api/v10/guilds/{guildId}/members?limit=1000`을 `Authorization: Bot <token>`으로 호출하고, 응답에서 이 시스템이 쓰는 필드만 뽑아 돌려준다: `{ discordUserId, username, isBot, joinedAt }`. 네트워크와 디스코드 응답 형식을 아는 유일한 파일이며, 테스트 대상이 아니다.
- **`apps/dashboard/lib/mutations/import-discord-members.ts`** (DB) — `importDiscordMembers(prisma, members: DiscordGuildMember[]): Promise<ImportDiscordMembersResult>`. 어댑터가 아니라 **이미 가져온 배열**을 받는다. 그래서 실제 디스코드 없이 통합 테스트할 수 있다.
- **`apps/dashboard/app/link-accounts/actions.ts`** — `importDiscordMembersAction`. 첫 줄에서 `requireAdmin()`, 그다음 어댑터 호출, 그다음 위 함수 호출.

이 분리는 전체 설계 문서의 원칙을 따른다: 외부 실계정·실API에 의존하는 부분은 얇은 어댑터로 떼어내고, 그 안쪽 로직만 테스트한다.

### 반영 규칙

- `user.bot`이 참인 계정은 건너뛴다(`skippedBots`로 센다).
- `discordUserId`로 기존 회원을 찾는다.
  - 있으면 `discordHandle`을 최신 값으로 갱신하고, `discordJoinedAt`이 비어 있으면 채운다. 다른 필드는 건드리지 않는다.
  - 없으면 `discordUserId`, `discordHandle`, `discordJoinedAt`만 채운 반쪽 레코드를 만든다. `elo`는 스키마 기본값 1000.
- `discordHandle`에는 디스코드 `username`(@핸들)을 저장한다. 표시 이름(`global_name`)은 사람이 자주 바꾸므로 쓰지 않는다.
- 전체를 한 트랜잭션으로 처리한다. 중간 실패 시 아무것도 반영되지 않는다.

### 제약과 실패

- **Server Members Intent가 꺼져 있으면 디스코드가 403을 준다.** 이 경우 "디스코드 개발자 포털에서 Server Members Intent를 켜야 합니다"라는 안내를 화면에 띄운다. 이 인텐트는 디스코드 앱 설정의 체크박스이며 사람이 한 번 켜야 한다.
- 한 번에 최대 1000명까지 받는다. 응답이 정확히 1000건이면 그 이상이 있을 수 있으므로 경고를 로그에 남긴다. 이 모임 규모에서는 도달하지 않는다.
- 디스코드가 429(레이트 리밋)를 주면 그대로 오류로 표시한다. 재시도 로직은 두지 않는다 — 관리자가 다시 누르면 된다.

## 카톡 닉네임 정규화

### 규칙

`packages/core`에 `normalizeKakaoNickname(raw: string): string`을 추가한다. 첫 번째 여는 괄호(`(` 또는 전각 `（`)부터 문자열 끝까지를 잘라내고 양끝 공백을 제거한다.

```
"유승수/98/ModCow#KR98(7시30분 도착)"  →  "유승수/98/ModCow#KR98"
"김민준/94/늑 대#1003"                  →  "김민준/94/늑 대#1003"  (변화 없음)
```

닫는 괄호를 요구하지 않는 이유는 실제 데이터에 `(8시 30분` 처럼 닫히지 않은 표기가 있기 때문이다. 괄호가 정당하게 들어간 닉네임은 뒷부분을 잃지만, 관측된 데이터에 그런 사례는 없고 잘린 값은 화면에서 바로 보이며 직접 수정할 수 있다.

### 적용 지점

- **임포트 시점** — `processKakaoExport`가 멘션에서 뽑은 닉네임을 정규화한 뒤 매칭·생성한다. 이러면 괄호 표기가 있는 날과 없는 날의 같은 사람이 하나로 붙는다.
- **실명 자동 채우기** — 회원을 새로 만들 때 정규화된 닉네임의 첫 `/` 앞 조각을 `realName`에 넣는다. 조각이 비어 있으면 넣지 않는다. **기존 회원의 `realName`은 절대 덮어쓰지 않는다** — 사람이 고친 값을 재업로드가 되돌리면 안 된다.

### 기존 데이터 정리 (일회성)

`packages/db/prisma/normalize-kakao-nicknames.ts` 스크립트를 만들어 한 번 실행한다. 한 트랜잭션 안에서:

1. `kakaoNickname`이 있는 모든 회원의 값을 정규화한다.
2. 정규화 결과가 같아진 회원들을 하나로 합친다.
   - **생존자 선택:** `discordUserId`가 있는 회원을 우선하고, 없으면 `createdAt`이 가장 이른 회원.
   - 나머지 회원의 `MentionLog`와 `GameParticipant`를 생존자로 옮긴다.
   - 생존자의 `lastActiveAt`은 병합 대상들 중 가장 최근 값으로 한다.
   - 생존자의 `realName`/`age`/`riotId`가 비어 있으면 병합 대상의 값으로 채운다.
   - 생존자의 `elo`는 유지한다. 병합으로 ELO를 합치거나 평균 내지 않는다 — 경기 기록에서 계산된 값이므로 임의 조작은 기록과 어긋난다.
   - 나머지 회원 행을 삭제한다.
3. `realName`이 비어 있는 회원을 정규화된 닉네임의 첫 조각으로 채운다.

스크립트는 실행 전후의 회원 수·활동기록 수와 병합한 쌍을 출력한다. 로컬 개발 DB에서 먼저 돌려 결과를 확인한 뒤 서버에서 같은 스크립트를 실행한다.

## 실명 수정

`/members` 표의 실명 칸을 관리자가 클릭하면 그 자리에서 입력창이 되고, 저장하면 `updateMemberRealName(prisma, memberId, realName)`을 호출하는 서버 액션이 실행된다. 빈 문자열은 `null`로 저장한다(화면에서는 `-`로 보인다). 비로그인 사용자에게는 편집 기능이 보이지 않으며, 서버 액션은 첫 줄에서 `requireAdmin()`을 호출한다.

실명 외의 필드는 이 화면에서 바꿀 수 없다.

## 정렬

`/members`는 `?sort=`와 `?dir=`을 읽는다.

- `sort`: `elo`(기본) / `realName` / `kakaoNickname`. 그 외 값은 기본값으로 취급한다.
- `dir`: `desc`(기본) / `asc`. 그 외 값은 기본값으로 취급한다.
- 정렬은 DB 쿼리에서 수행한다. 값이 비어 있는 행은 방향과 무관하게 마지막에 둔다 — 실명이 없는 회원이 목록 맨 위를 차지하면 쓸모가 없다.
- 표 헤더의 실명·카톡 닉네임·ELO를 누르면 해당 기준으로 정렬하고, 이미 그 기준이면 방향을 뒤집는다. 현재 기준과 방향은 헤더에 화살표로 표시한다.
- 기존 필터(`filter`)·검색(`q`)과 함께 동작하며, 링크는 기존 쿼리스트링을 유지한다.

## 에러 처리

- **디스코드 403(인텐트 꺼짐)** — 화면에 켜야 한다는 안내를 보여준다. 다른 오류는 디스코드가 준 상태 코드와 함께 짧은 한글 문구로 표시한다.
- **가져오기 중 DB 실패** — 트랜잭션이 롤백되므로 부분 반영이 남지 않는다.
- **실명 저장 실패** — 해당 행에만 오류를 표시하고 나머지 표는 그대로 둔다.
- **정규화 스크립트 실패** — 트랜잭션 롤백. 스크립트는 여러 번 실행해도 결과가 같아야 한다(이미 정규화된 값은 그대로, 병합할 중복이 없으면 아무 것도 하지 않음).

## 테스트 전략

- **`normalizeKakaoNickname`** — 순수 함수 단위 테스트: 괄호 있는 경우, 없는 경우, 닫히지 않은 괄호, 전각 괄호, 괄호만 있는 문자열.
- **`importDiscordMembers`** — `DATABASE_URL_TEST` 대상 통합 테스트: 신규 생성, 기존 회원 핸들 갱신, 봇 제외, 이미 카톡으로만 있는 회원은 건드리지 않음(연결은 수동이므로), 빈 배열.
- **`processKakaoExport`** — 기존 테스트에 괄호 표기 케이스를 추가: 괄호가 붙은 멘션과 안 붙은 멘션이 같은 회원으로 모이는지, 신규 생성 시 `realName`이 채워지는지, 기존 회원의 `realName`이 덮어써지지 않는지.
- **`updateMemberRealName`** — 통합 테스트: 저장, 빈 문자열 → `null`, 없는 회원 id.
- **정렬** — `getMemberListData`의 단위/통합 테스트: 세 기준 각각의 오름·내림, 빈 값이 마지막에 오는지, 잘못된 파라미터가 기본값으로 떨어지는지.
- **정규화 스크립트** — 통합 테스트: 중복 병합 시 활동기록이 생존자로 옮겨지는지, 생존자 선택 규칙, 재실행해도 결과가 같은지.
- **디스코드 어댑터** — 테스트하지 않는다. 실제 API 호출은 관리자가 버튼을 눌러 확인한다.

## 알려진 한계

- **연결은 여전히 수동이다.** 디스코드 회원을 가져와도 카톡 계정과 이어주는 것은 관리자가 `/link-accounts`에서 직접 한다. 자동 매칭은 이름 표기가 제각각이라 오연결 위험이 크다.
- **`/link-accounts`의 카톡 목록은 파싱되는 닉네임만 보여준다.** `실명/나이/닉네임#태그` 형태로 갈라지지 않는 닉네임(예: `모임장`)은 연결 대상 목록에 나오지 않는다. 이번 작업에서 바꾸지 않는다.
- **괄호를 정당하게 쓰는 닉네임은 잘린다.** 위 규칙의 의도된 대가다.
- **가져오기는 사람이 눌러야 한다.** 새 멤버가 디스코드에 들어와도 버튼을 누르기 전까지는 시스템에 없다.

## 배포 반영

구현이 끝나면 서버에 재배포한다: `git archive HEAD`로 소스 전송 → `sudo docker compose -f docker-compose.prod.yml build` → `up -d`. 정규화 스크립트는 서버 DB에도 한 번 실행한다. 이 서버는 `ubuntu` 계정이 docker 그룹에 없어 모든 docker 명령에 `sudo`가 필요하다.
