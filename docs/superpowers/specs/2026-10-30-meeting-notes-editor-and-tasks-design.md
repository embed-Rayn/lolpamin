# 회의록 편집 화면 개선 + 할 일 추적 설계

작성일: 2026-10-30
기존 설계: `2026-10-02-meeting-notes-design.md` (권한·충돌 검사·이미지 규칙은 그대로)

## 목적

회의록(`/meeting-notes`)의 UX를 일반적인 노트 서비스 수준으로 올린다. 사용자 피드백은
"전반적인 UX가 마음에 안 든다"였고, 직접 겪은 문제는 번호 목록·들여쓰기가 깨지는 것이었다
(본문은 2026-10-30에 표준 마크다운 `react-markdown` + `remark-gfm` + `remark-breaks`로
바뀌었다 — `MeetingNoteBody`). 남은 불편은 셋이다.

1. 편집/미리보기가 탭 전환이라 쓰면서 결과를 못 본다.
2. 표준 마크다운의 들여쓰기 규칙(`1. ` 아래 3칸)을 손으로 맞춰야 한다.
3. 쓰다 창을 닫으면 내용이 날아간다.

그리고 회의에서 나온 **할 일**을 누가 맡았고 끝났는지 챙길 곳이 없다. 회의록 글 하나가 그대로
할 일 목록이 되게 한다.

## 목표

- 좌우 분할 편집기, 편집 보조(Tab 들여쓰기, Enter로 목록 잇기, 툴바), 브라우저 임시저장.
- 본문의 체크박스 할 일에 담당자(`@이름`)와 기한(`~M/D`)을 적으면 읽어 낸다.
- 보기 화면과 편집 미리보기에서 체크박스를 바로 체크한다.
- 모든 회의록의 미완료 할 일을 담당자별로 모아 보는 화면.

## 하지 않는 것 (비목표)

- 실시간 동시 편집. 기존 `version` 충돌 거부를 그대로 쓴다.
- 할 일을 회의록과 별도 테이블로 관리(칸반, 상태 3단계). 할 일의 원본은 언제나 본문 글자다.
- 담당자를 회원·관리자 명단과 맞추기, `@` 자동완성.
- 임시저장의 기기 간 동기화(서버 저장).
- 검색, 템플릿, 이전/다음 회의록 이동 — 이번 범위가 아니다.
- 모바일 지원. 회의록은 계속 `desktopOnly`다.

## 실패로 볼 것 (반목표)

- 체크 한 번이 다른 운영진이 쓰던 글을 조용히 덮어쓰는 것.
- 할 일 화면이 본문과 다른 말을 하는 것 — 본문에서 지운 할 일이 남아 있거나, 체크한 할 일이
  본문에는 `[ ]`로 남는 것.
- 편집 보조가 평범한 타이핑을 방해하는 것(코드 블록 안에서 Tab이 엉뚱하게 동작하는 등).

## 1. 할 일 추적

### 쓰는 법

본문의 GFM 체크박스 줄이 할 일이다. 하위 목록 안에 있어도 된다.

```
- [ ] @소영 @병준 날짜 후보 산출 ~11/14
   - [x] @승한 가게 예약
```

- **담당자**: 줄 안의 `@` 뒤 공백 전까지가 한 사람. 여러 명 가능. 대소문자를 접어 같은 사람으로
  본다(`@Rayn`과 `@rayn`). 명단과 맞추지 않는다 — 적힌 글자 그대로 묶는다.
- **기한**: `~M/D` (예 `~11/14`). 연도는 그 회의록의 회의일(`meetingDate`) 기준 — 회의일보다
  앞선 월/일이면 다음 해. `~2026/11/14`처럼 연도를 적으면 그대로 쓴다. 날짜로 읽히지 않으면
  (`~13/40`) 기한이 아니라 글자로 둔다.
- **물려받기** (사용자 결정): 할 일은 조상 목록 항목(할 일이든 아니든)의 담당자·기한을 물려받는다.
  담당자와 기한은 따로 본다 — 가장 가까운 조상 중 `@`를 적은 항목의 담당자, `~`를 적은 항목의
  기한. 자기 줄에 `@`/`~`를 적으면 그 값이 대신한다(더하지 않는다).
  ```
  2. 캠핑 @병준 ~11/14
     - [ ] 후보 날짜 정리            → @병준, 11/14 (둘 다 물려받음)
     - [ ] @소영 장소 알아보기 ~11/10 → @소영, 11/10 (둘 다 자기 것)
       - [ ] 펜션 전화              → @소영, 11/10 (바로 위 할 일에서)
  ```
  조상 관계는 들여쓰기로 판단한다: 어떤 목록 줄의 조상은 그보다 덜 들여쓴 앞쪽 목록 줄들이다.
  제목 줄, 또는 들여쓰지 않은 목록 아닌 줄을 만나면 조상 사슬을 끊는다. 빈 줄은 끊지 않는다.
- 할 일의 표시 텍스트는 담당자·기한 표기를 뺀 나머지다. 보기 화면의 본문에서는 원문을 그대로
  보여 준다(담당자 칩 같은 장식은 할 일 화면에만).

### 추출 (`packages/core`)

순수 함수 `extractMeetingNoteTasks(body, meetingDate)` → 할 일 배열
`{ line, checked, text, assignees, due, parentText }`. `line`은 본문의 0부터 센 줄 번호.
`parentText`는 가장 가까운 조상 목록 항목의 표시 텍스트(없으면 null) — 할 일 화면에서 「캠핑 ›
후보 날짜 정리」처럼 맥락을 흐리게 보여 준다(제 판단).

- 줄 단위 정규식으로 읽는다: 앞 공백, 글머리(`-`/`*`/`+` 또는 `N.`/`N)`), 공백, `[ ]`/`[x]`/`[X]`, 공백.
- 펜스 코드 블록(```` ``` ````/`~~~`) 안의 줄은 할 일이 아니다.
- 인용(`>`) 안의 체크박스는 추출하지 않는다(제 판단: 드문 경우이고 줄 정규식을 단순하게 둔다).
  이 경우 렌더러는 체크박스를 그리지만 누를 수는 없다.
- 단위 테스트로 `react-markdown`이 체크박스로 그리는 줄과 이 함수가 잡는 줄이 같은지를 대표
  사례로 고정한다(위의 인용 예외는 명시).

### 체크하기

보기 화면(`/meeting-notes/[id]`), 할 일 화면, 편집기 미리보기에서 체크박스를 누를 수 있다.

- **보기 화면·할 일 화면**: 서버 액션 `toggleMeetingNoteTask(noteId, line, expectedText, checked)`.
  현재 본문의 `line`번째 줄이 여전히 같은 할 일(체크 표시를 뺀 텍스트가 `expectedText`)이면 그
  줄의 `[ ]`/`[x]`만 바꿔 저장한다. 다르면(그 사이 본문이 바뀌어 줄이 밀림) 거부하고
  "회의록이 바뀌었습니다. 새로 고침해 주세요."를 띄운다.
  - 이 저장은 `version` 비교를 하지 않는다(체크는 남의 글을 덮지 않는 한 줄 수정이라). 대신
    `version`을 올리고 `updatedById`를 누른 사람으로 남긴다. 그 회의록을 편집 중이던 운영진의
    저장은 아래 「저장 충돌」 규칙을 탄다 — 체크만 바뀐 경우 막히지 않는다.
  - 줄 확인과 쓰기는 한 트랜잭션 안에서, 읽은 `version`을 조건으로 `updateMany`해 그 사이 끼어든
    저장과 경합하지 않게 한다(경합하면 같은 "바뀌었습니다" 안내).
  - 버튼은 누르는 즉시 낙관적으로 바뀌고, 실패하면 되돌린다.
- **편집기 미리보기**: 서버에 가지 않는다. 왼쪽 글의 해당 줄 `[ ]`↔`[x]`만 바꾼다(저장은 평소대로).
- 미리보기·보기의 체크박스 → 줄 번호 연결은 `react-markdown`이 넘기는 노드의 소스 위치
  (`node.position.start.line`)로 한다.

### 할 일 화면

회의록 목록 위에 「회의록 / 할 일」 탭. 할 일 탭은 `/meeting-notes/tasks`(관리자 전용, 기존
회의록 페이지와 같은 로그인 리다이렉트, `desktopOnly`).

- 모든 회의록의 본문을 읽어 `extractMeetingNoteTasks`로 모은다. 회의록은 수십 건 규모라
  저장 컬럼 없이 읽을 때 계산한다(카톡 매치 키와 같은 판단).
- **묶음**: 담당자별. 담당자가 여럿인 할 일은 각 담당자 묶음에 모두 나온다. 담당자 없는 할 일은
  「미지정」 묶음(맨 뒤). 묶음 순서는 미완료 수가 많은 순(제 판단).
- **각 줄**: 체크박스, (흐린 `parentText ›`) 할 일 텍스트, 기한, 출처(회의일 · 회의록 제목 — 누르면 그 회의록으로).
- **정렬**: 기한 있는 것 먼저 기한 순, 기한 없는 것은 그 아래 회의일 최신 순.
- **기한 강조**: 지남 = 빨강(`text-danger-soft`), 3일 이내 = 주황(`text-orange`) (3일은 제 판단).
  날짜 비교는 서울 날짜 기준.
- **완료 포함** 토글(URL `?done=1`): 끄면 미완료만, 켜면 완료도 흐리게 함께.
- 할 일이 하나도 없으면 쓰는 법(`- [ ] @이름 할 일 ~11/14`)을 보여 주는 빈 화면.

## 2. 편집 화면

### 좌우 분할

`MeetingNoteEditor`의 편집/미리보기 탭을 없애고 좌(글) · 우(결과) 2열로 둔다. 제목·회의일
입력과 저장 버튼은 위에 그대로. 오른쪽은 `MeetingNoteBody`를 그대로 쓰고 체크박스만 눌리게 한다
(위 「체크하기」). 두 열은 각자 스크롤하고, 오른쪽은 왼쪽 커서가 있는 줄 근처로 대략 따라간다
(소스 줄 번호 ↔ 렌더된 블록의 `data-line` 같은 표식; 정확도는 블록 단위면 충분 — 구현 방식은
빌더 몫).

### 편집 보조

textarea 위의 키 처리. 펜스 코드 블록 안에서는 Enter 자동 글머리를 하지 않는다(Tab은 그냥
들여쓰기).

- **Tab / Shift+Tab**: 커서 줄(선택이 여러 줄이면 그 줄 전부)을 들여쓰기/내어쓰기. 한 단계의
  폭은 **윗줄 글머리의 글자 시작 위치**까지다 — `1. ` 아래는 3칸, `- ` 아래는 2칸, `10. ` 아래는
  4칸. 그래서 들여쓴 줄은 언제나 표준 마크다운의 하위 목록이 된다. 윗줄이 목록이 아니면 2칸.
  Tab이 포커스를 다음 칸으로 옮기지 않는다.
- **Enter**: 목록(`- `), 번호(`N. `), 할 일(`- [ ] `) 줄 끝에서 Enter → 다음 줄에 같은 들여쓰기와
  글머리. 번호는 +1, 할 일은 언제나 `[ ]`로. 글머리만 있는 빈 줄에서 Enter → 그 글머리를 지우고
  목록을 끝낸다(들여쓴 빈 줄이면 한 단계 내어쓰기 — 일반 노트 앱 동작, 제 판단).
  IME 조합 중(`isComposing`)의 Enter는 건드리지 않는다 — 한글 입력이 깨진다.
- **툴바**: 제목(`## `), 굵게, 목록, 번호, 할 일, 들여쓰기, 내어쓰기, 이미지. 줄 단위 버튼은 커서
  줄(들)의 앞을 토글, 굵게는 선택을 `**`로 감싸기/풀기, 이미지는 기존 파일 선택 업로드.
- **단축키**: Ctrl+B 굵게. (그 외 단축키는 넣지 않는다.)
- 모든 보조 동작은 브라우저 실행 취소(Ctrl+Z)가 한 단계로 되돌릴 수 있어야 한다
  (`document.execCommand("insertText")` 또는 동등한 방법 — 방식은 빌더 몫, 단 Ctrl+Z가 깨지면 실패).
- 편집기 아래 서식 안내 문구는 단축키 위주로 줄인다.

### 저장 충돌 (사용자 결정)

지금은 충돌이 나면 안내만 뜨고 다시 저장할 길이 없다. 체크가 `version`을 올리게 되면서 충돌이
흔해지므로, 충돌 뒤의 흐름을 정한다.

편집기는 연 시점의 `baseVersion`과 함께 **`baseBody`/`baseTitle`/`baseMeetingDate`**(연 시점의 서버
값)를 들고 있다. 저장이 버전 충돌로 거부되면 액션은 에러 문자열 대신 서버의 현재 값
`{ title, meetingDate, body, version, updatedByName, updatedAt }`을 돌려준다.

1. **체크만 바뀐 경우 — 자동 반영**: 제목·회의일이 base와 같고, 본문이 base와 줄 수가 같으며 모든
   줄이 체크 표시(`[ ]`↔`[x]`)를 무시하면 같을 때. 순수 함수
   `rebaseMeetingNoteToggles(baseBody, serverBody, myBody)`(core)가 서버에서 체크 상태가 바뀐 각
   할 일을 내 본문에서 찾아(같은 할 일 텍스트, base와 같은 체크 상태인 줄이 정확히 하나일 때만)
   서버 상태로 맞춘다. 내가 지웠거나 고친 할 일은 건너뛴다. 그 결과를 서버의 `version`으로 곧바로
   다시 저장한다. 사용자에게는 「다른 운영진의 체크 N건을 반영해 저장했습니다」를 잠깐 보여 준다.
   다시 저장이 또 충돌하면 같은 판단을 한 번 더 하고, 그래도 안 되면 2번으로 간다.
2. **글이 바뀐 경우 — 충돌 화면**: 편집기 위에 충돌 패널. 「○○님이 HH:mm에 수정했습니다」와 함께
   상대 버전 / 내 버전을 나란히(원문 글자, 읽기 전용) 보여 주고 둘 중 하나를 고른다.
   - **내 것으로 덮어쓰기**: 확인 한 번 뒤 서버의 `version`으로 내 값을 저장한다.
   - **상대 것 불러오기**: 내 값(제목·회의일·본문·imageIds)을 보관 키
     `lolpamin.meeting-note.stash.<id>`에 넣고, 편집기를 서버 값으로 다시 연다(base도 서버 값으로).
     편집기 옆에 「보관한 내 글」 접힌 패널이 생겨 복사해 갈 수 있고, 「보관 삭제」로 지운다.
   - 줄 단위 병합(diff 표시, 부분 선택)은 하지 않는다.
3. 임시저장을 불러온 경우도 같은 흐름이다 — 임시저장에 `baseBody` 등이 함께 들어 있으므로 체크만
   바뀐 경우는 자동 반영되고, 아니면 충돌 화면이 뜬다.

`updateMeetingNote`의 버전 조건부 갱신 자체는 그대로 둔다. 충돌 시 현재 값을 읽어 돌려주는 것과
「덮어쓰기」가 새 `expectedVersion`으로 다시 부르는 것만 더해진다.

### 임시저장

- 내용이 바뀌면 약 2초 뒤(디바운스) `localStorage`에 저장. 키는 새 글 `lolpamin.meeting-note.draft.new`,
  수정 `lolpamin.meeting-note.draft.<id>`. 값은 `{ title, meetingDate, body, imageIds, baseVersion,
  baseTitle, baseMeetingDate, baseBody, savedAt }`(새 글이면 base 값들은 null).
- 편집기를 열 때 그 키에 서버 값과 다른 임시저장이 있으면 상단에 안내 줄: 「저장하지 않은 내용이
  있습니다 (M/D HH:mm) — 불러오기 / 버리기」. 자동으로 덮어쓰지 않는다.
- 수정 글에서 `baseVersion`이 현재 `version`과 다르면 안내에 「그 사이 ○○님이 수정했습니다」를
  덧붙인다. 불러오면 편집기의 base 값들을 **임시저장의 base 값들**로 둔다 — 저장 때 위 「저장 충돌」
  규칙을 타서, 체크만 바뀌었으면 자동 반영되고 글이 바뀌었으면 충돌 화면이 뜬다.
- 저장 성공, 「버리기」, 회의록 삭제 시 그 키를 지운다.
- 알려진 한계: 저장 안 한 글에 올린 이미지는 24시간 뒤 서버에서 지워지므로, 하루 넘게 묵은
  임시저장을 불러오면 그 이미지는 「이미지 없음」으로 나온다. 안내만 하고 막지 않는다.
- `localStorage`를 못 쓰는 브라우저(사생활 모드 등)에서는 조용히 임시저장 없이 동작한다.

## 제약

- 기존 규칙 유지: 읽기·쓰기 관리자 전용, `/api/meeting-notes/images/[id]` 404 규칙, raw HTML 렌더
  금지, 본문 50,000자, `desktopOnly`.
- 도메인 로직(할 일 추출과 물려받기, 기한 해석, 들여쓰기 폭 계산, 줄 토글, 체크 자동 반영)은 `packages/core`의 순수 함수 +
  단위 테스트. DB 쓰기는 `apps/dashboard/lib/mutations/meeting-notes.ts`, `prisma` 첫 인자, 통합
  테스트(`DATABASE_URL_TEST` 가드 유지).
- 스키마 변경 없음.
- 색은 시맨틱 토큰만(`text-danger-soft`, `text-orange` 등), hex 금지.
- UI 문구 한국어, 코드·주석 영어. `CLAUDE.md`의 회의록 단락을 새 동작으로 갱신.
